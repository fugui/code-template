## 1. 新模块接入 CodeBench 15 项必过自检表（Checklist）

### A. 架构契约与命名隔离
- [ ] **1. 唯一模块标识**：`module_key` 为纯小写字母/数字/下划线，未与平台保留路由冲突，且前后端 `ModuleKey`、`vite.config.ts` 的 `federation.name`、`code-bench/config.yaml` 的 `gateways.<key>` 三处完全一致。
- [ ] **2. Base 路径规范**：`frontend/vite.config.ts` 中 `base` 已配置为 `'/<module_key>/'`（**首尾均包含 `/` 斜杠**）。
- [ ] **3. 数据库表名前缀**：所有新增业务 GORM 模型均已实现 `TableName()` 并携带模块专属前缀（如 `mon_*`），未修改或污染共享表 `users`、`departments`、`sys_audit_logs`。
- [ ] **4. 嵌入式 Router 规范**：`App.tsx` 在 `isEmbedded === true` 分支下**未重复包裹 `<BrowserRouter>`**，且隐藏了独立调试侧栏与顶栏。

### B. 安全鉴权与代码质量
- [ ] **5. 密钥与配置合规**：源码与 Git 历史中无任何硬编码密码或固定 JWT Secret，`config.yaml` 已被 `.gitignore` 忽略。
- [ ] **6. 严苛错误处理与类型检查**：Go 后端无任何 `_ = err` 错误忽略，`make test`（含 `go vet`）全绿；前端无任何 `any` 类型，`make lint` 零报错。
- [ ] **7. 服务端 RBAC 与归属校验**：管理类 API 已挂载 `commonAuth.RequireAdmin("<key>_admin")`，普通写接口已在服务端校验资源创建人/负责人权限，未仅靠前端隐藏按钮。
- [ ] **8. 操作审计接入**：核心增、删、改接口已调用 `commonAudit.SetAuditContext` 记录变更前后快照，并在 CodeBench「操作审计」页面验证可查。

### C. UI 交互与双模主题体验
- [ ] **9. 亮/暗双模零黑块**：在独立模式或门户顶栏反复切换 **亮色（Light）** 与 **暗黑（Dark）** 主题，所有卡片、表头、弹窗、输入框、文字对比度清晰自然，无硬编码 `#fff` / `#000` / `#111827`。

## 2. 高频问题排查手册（FAQ）

### Q1：点击左侧菜单报错 `Failed to fetch dynamically imported module: .../remoteEntry.js`？
* **排查步骤 1（忘记构建前端产物）**：CodeBench 加载的是子模块后端内嵌托管的 `frontend/dist/assets/remoteEntry.js`，而不是 Vite `npm run dev` 开发端口！若只跑了 `go run .` 而未构建前端，或改了前端没重新 `make build`，就会 404。请执行 `make build` 并重启子服务。
* **排查步骤 2（`base` 缺少末尾斜杠）**：检查 `frontend/vite.config.ts`，确认 `base: '/monitor/'` 末尾有 `/`；若写成 `'/monitor'`，分片资源路径会拼接错误。
* **排查步骤 3（进程未启动或端口不通）**：在终端执行 `curl -I http://127.0.0.1:8091/monitor/assets/remoteEntry.js` 检查子模块自身是否正常响应 `200`。

### Q2：菜单能正常加载，但页面发起 API 请求报 `404 API route not found`？
* **原因 A**：`main.go` 中调用 `commonServer.Run` 时漏传了 `Prefix: config.ModuleKey`（或 `Prefix` 与 `gateways` 键名不一致），导致网关转发过来的 `/monitor/api/items` 没有剥离 `/monitor` 前缀。
* **原因 B**：前端未在 `App.tsx` 顶层调用 `setupFetchInterceptor({ appPrefix: '/monitor' })`，且直接使用原生 `fetch('/api/items')`，导致请求打到了宿主 `code-bench` 的 `/api/items` 而非 `/monitor/api/items`。

### Q3：独立模式登录正常，但嵌入 CodeBench 后所有 API 都返回 `401 Unauthorized`？
* **根因**：子模块 `config.yaml` 中的 `auth.jwt_secret` 与 `code-bench/config.yaml` 中的 `auth.jwt_secret` **不一致**（或者子模块未创建 `config.yaml`，每次重启随机生成了临时密钥）。
* **解决**：将两边的 `auth.jwt_secret` 配置为完全相同的密钥字符串并重启子服务。

### Q4：点击按钮进入子模块页面时报 `You cannot render a <Router> inside another <Router>`？
* **根因**：在 `isEmbedded === true` 嵌入模式下，子模块内部又渲染了一层 `<BrowserRouter>`。
* **解决**：参考模板 `frontend/src/App.tsx`，通过 `const effectiveEmbedded = isEmbedded || Boolean(window.__POWERED_BY_PORTAL__)` 判断，嵌入模式下直接返回 `<Routes>...</Routes>`。

### Q5：调用 `useConfirm()` 弹出了浏览器丑陋的原生弹窗，或者 `useToast()` 报错 `must be used within a ToastProvider`？
* **根因**：`@code/common` 未放入 `federation.shared`，子模块与宿主拥有各自独立的 React Context 实例。
* **解决**：确保子模块 `App.tsx` 最外层包裹了来自 `@code/common` 的 `<ConfirmProvider>` 与 `<ToastProvider>`（模板已默认配好，请勿删除）。

### Q6：切换到亮色主题（Light Mode）后，部分表格或卡片背景依然是深黑色、文字看不清？
* **根因**：CSS 或 JSX `style` 中硬编码了暗色值（如 `#1e293b`、`#0f172a`、`#fff`）。
* **解决**：全文检索 `#` 与 `rgb(`，全部替换为 `var(--color-bg-surface)`、`var(--color-bg-muted)`、`var(--color-text-primary)` 等 `theme.css` 标准语义变量。
