# 03 - 后端开发与公共能力集成指南 ⚙️

本文介绍子模块 Go 后端如何深度复用 `code-common/backend` 提供的微服务骨架、JWT/RBAC 统一鉴权、共享数据库模型、异步操作审计以及物理隔离单元测试。

---

## 1. 统一服务骨架与网关前缀自动剥离 (`commonServer.Run`)

CodeBench 网关会将前端发往 `/<module_key>/api/*` 与 `/<module_key>/assets/*` 的请求**原样保留路径**反向代理给子模块后端。  
通过使用 `code-common/backend/server` 中的 `Run` 启动服务并声明 `Prefix: config.ModuleKey`（见 `main.go`）：

```go
err := commonServer.Run(commonServer.Options{
    ServiceName:      config.ServiceName,
    Prefix:           config.ModuleKey, // 例如 "monitor"，底层自动剥离 /monitor 前缀！
    Port:             config.AppConfig.Server.Port,
    FrontendFS:       &frontendFS,      // 托管 go:embed 打包的前端静态产物与 SPA 回退
    FrontendDistPath: "frontend/dist",
    RegisterRoutes:   RegisterAPIRoutes,
})
```

**核心收益**：
* 外部网关请求 `GET /monitor/api/items` 到达本服务时，`commonServer` 会先将 `req.URL.Path` 自动剥离为 `/api/items` 再交给 Gin。
* 本地独立调试直接请求 `GET /api/items` 时，同样匹配 `/api/items`。
* **业务开发者在 `RegisterAPIRoutes` 中永远只需要编写干净、统一的 `/api/...` 路由**，彻底告别环境路径硬编码！

## 2. 路由分级与统一 JWT / RBAC 鉴权 (`commonAuth`)

根据团队安全规范，所有后端 API 在 `main.go` 的 `RegisterAPIRoutes` 中集中注册，严格划分为三层：

### 2.1 免密开放路由 (`Unprotected`)
仅放置健康检查（`/api/health`）以及独立调试登录所需的最小端点（生产环境将 `auth.standalone_mode` 设为 `false` 即可关闭本地账密登录入口）。

### 2.2 受保护业务路由 (`AuthMiddleware`)
挂载 `commonAuth.AuthMiddleware`：

```go
protected := r.Group("/api")
protected.Use(commonAuth.AuthMiddleware(commonAuth.AuthConfig{
    JWTSecretGetter: func() string { return config.AppConfig.Auth.JWTSecret },
    DB:              models.DB,
    PreloadAssocs:   []string{"Department"},
}))
```

在业务 Handler 中通过 `commonAuth.GetUserContext(c)` 读取标准化身份信息：

```go
uc := commonAuth.GetUserContext(c)
// uc.UserID         -> uint   当前登录用户主键 ID
// uc.Username       -> string 用户名/邮箱
// uc.Name           -> string 中文姓名
// uc.EmployeeID     -> string 工号
// uc.DepartmentID   -> *uint  所属部门 ID
// uc.DepartmentName -> string 所属部门名称
// uc.Roles          -> []string 角色列表（如 ["monitor_admin"]）
```

### 2.3 模块管理员路由 (`RequireAdmin`)
平台采用统一的 RBAC 角色约定：
* **`super_admin`**：平台超级管理员，调用 `RequireAdmin(...)` 时**自动放行所有子模块管理接口**。
* **`<module_key>_admin`**（如 `monitor_admin`）：本业务模块的专属管理员（由超级管理员在 CodeBench「用户管理」页面中勾选分配，角色字符串自动存入 `users.roles` JSON 数组）。

挂载方式：
```go
admin := protected.Group("/admin")
admin.Use(commonAuth.RequireAdmin(config.AdminRole))
{
    admin.GET("/settings", handlers.GetModuleSettings)
    admin.PUT("/settings", handlers.UpdateModuleSettings)
}
```

### 2.4 资源级归属校验（防水平越权 IDOR）
对于普通成员可创建的业务资源，修改和删除接口必须在服务端靠近数据层处校验所有权（参考 `handlers/item.go` 中的 `canModifyItem`）：仅创建人、负责人或模块管理员允许变更，绝不盲目信任前端隐藏按钮的限制。

## 3. 共享数据库治理与表名隔离规范（必读！）

为了跨模块无缝关联组织架构（`User` / `Department`）并汇总全局审计日志（`SysAuditLog`），各业务子模块默认连接同一个 PostgreSQL 数据库。开发数据模型时必须严格遵守以下 **3 条铁律**：

1. **禁止重复定义核心实体**：`User`、`Department`、`SysAuditLog` 必须通过类型别名直接复用 `code-common/backend/models`（见 `models/item.go`），且严禁对这些公共表执行破坏性列删除或类型篡改。
2. **强制添加模块表名前缀**：所有本模块新建的 GORM 模型，**必须实现 `TableName() string` 方法**并拼接 `config.TablePrefix`（例如 `mon_alerts`、`mon_rules`），严禁使用无前缀的 `items`、`tasks`、`settings`、`logs` 等通用表名！
   ```go
   func (MonitorRule) TableName() string {
       return config.TablePrefix + "rules" // 实际建表名: mon_rules
   }
   ```
3. **严禁拼接 SQL 与泄漏敏感字段**：
   * 查询条件一律使用 GORM 参数化占位符 `Where("name LIKE ?", "%"+search+"%")`。
   * 关联查询 `Preload("Owner")` 返回前端前，清理无需暴露的敏感/隐私字段（如 `Owner.Password = ""`、`Owner.Email = ""`）。
   * 严禁使用 `_ = err` 吞掉任何数据库或 IO 错误！

## 4. 统一分页响应封装 (`utils.ParsePagination` & `PaginatedJSON`)

列表查询接口请统一使用 `code-common/backend/utils` 处理分页参数与输出，以直接匹配前端 `@code/common` 的 `<Pagination />` 组件：

```go
// 解析 ?page=1&pageSize=25，默认 25 条/页，单页上限 100 条
page, pageSize, offset := utils.ParsePagination(c, 25, 100)

// ... 执行 GORM Count(&total) 与 Offset(offset).Limit(pageSize).Find(&items) ...

// 输出标准 JSON: { "items": [...], "total": 120, "page": 1, "pageSize": 25, "totalPages": 5 }
utils.PaginatedJSON(c, items, total, page, pageSize)
```

## 5. 接入平台全局操作审计 (`commonAudit`)

模板已在 `main.go` 中初始化了 `commonAudit.Init(models.DB)` 并挂载 `commonAudit.Middleware(config.ModuleKey)`，同时在 `OnShutdown` 钩子中调用 `commonAudit.Close(ctx)` 确保停机前缓冲队列全部落盘。

在增、删、改 Handler 中，只需调用一行 `commonAudit.SetAuditContext`，审计中间件便会自动计算 `before` 与 `after` 结构体的字段级差异（自动脱敏密码/密钥字段），并异步批量写入平台审计中心（可在 CodeBench「操作审计」页面直接检索和查看 Diff 抽屉！）：

```go
commonAudit.SetAuditContext(
    c,
    "rule",                                      // 子功能分类
    "update",                                    // 动作: create / update / delete / trigger
    commonModels.AuditLevelP1,                   // 风险等级: AuditLevelP0(高危) / P1(重要) / P2(常规)
    fmt.Sprintf("更新告警规则 [%s]", after.Name), // 人类可读摘要
    "monitor_rule",                              // 目标资源类型
    strconv.FormatUint(uint64(after.ID), 10),    // 目标资源 ID
    after.Name,                                  // 目标资源名称
    beforeSnapshot,                              // 变更前结构体快照（新建传 nil）
    after,                                       // 变更后结构体快照（删除传 nil）
)
```

## 6. 编写物理隔离的数据库单元测试 (`testdb.SetupIsolatedDB`)

严禁在单元测试中直接连接开发库或生产库！`code-common/backend/testdb` 提供了带生产库熔断保护的一次性隔离建库工具（参考 `handlers/item_test.go`）：

```go
func TestRuleCRUD(t *testing.T) {
    // 若未设置 TEST_DB_DSN 环境变量会自动优雅 Skip；
    // 若设置了 TEST_DB_DSN（仅允许指向 postgres 管理库或 *_test 库），会自动创建独立临时库并在测试结束时自动 DROP！
    isolatedDB := testdb.SetupIsolatedDB(t, config.ModuleKey)
    if err := models.SetupWithDB(isolatedDB); err != nil {
        t.Fatalf("初始化测试库失败: %v", err)
    }
    // ... 使用 httptest 执行真实 SQL 读写断言 ...
}
```

运行带数据库集成的完整测试命令：
```bash
TEST_DB_DSN="host=127.0.0.1 port=5432 user=postgres password=xxx dbname=postgres sslmode=disable" make test
```
