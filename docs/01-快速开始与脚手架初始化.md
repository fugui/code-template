# 01 - 快速开始与脚手架初始化 🚀

本文指导开发者在 **5 分钟内** 基于 `code-template` 初始化一个全新的业务功能模块，分别验证 **本地独立调试运行** 与 **挂载到 CodeBench 组装台运行**。

---

## 1. 环境与目录结构前置要求

### 1.1 基础软件依赖
* **Go**：`1.22+`（工作区当前标准为 `1.26.x`）
* **Node.js & npm**：Node `20+`，npm `10+`
* **PostgreSQL**：`14+`（用于本地持久化与联调）
* **Python 3**：`3.8+`（仅在执行一键初始化脚本 `init-module.sh` 时使用）
* **GNU Make**：统一执行构建、测试与静态检查

### 1.2 多仓并排工作区约定（重要！）
平台采用多仓库共享公共库 `code-common` 的组织方式（Go 端通过 `replace code-common/backend => ../code-common/backend` 引用，前端通过 `"@code/common": "file:../../code-common/frontend"` 引用）。  
因此，请务必将 `code-common`、`code-bench` 与你的新模块放在**同一个父级工作区目录**下：

```text
codes/                        # 父级工作区目录
├── code-common/              # 【必需】前后端公共基础资产库
├── code-bench/               # 【联调推荐】微前端宿主组装台（默认 :8000）
├── code-template/            # 标准模块模板仓库（默认 :8090）
└── code-monitor/             # 你即将派生创建的新业务模块（例如 :8091）
```

## 2. 使用 `init-module.sh` 一键派生新模块

假设你要开发一个名为 **「集群监控诊断」** 的新业务模块，选定英文唯一标识为 `monitor`。

### Step 1：选择初始化方式

`init-module.sh` 脚本非常智能，支持以下两种派生方式：

* **方式 A：在父级工作区直接执行（最推荐 ⭐）**  
  在 `codes/` 目录下直接调用模板脚本，脚本会自动识别模板工程，将干净源码复制到新目录 `code-monitor` 并完成全链路替换与 Git 初始化：
  ```bash
  code-template/scripts/init-module.sh \
    --key monitor \
    --title "集群监控诊断" \
    --port 8091 \
    --dev-port 5181 \
    --table-prefix mon_ \
    --icon Activity
  ```
* **方式 B：克隆或复制后在目标目录就地初始化**  
  ```bash
  git clone git@github.com:fugui/code-template.git code-monitor
  cd code-monitor
  bash scripts/init-module.sh \
    --key monitor \
    --title "集群监控诊断" \
    --port 8091 \
    --dev-port 5181 \
    --table-prefix mon_ \
    --icon Activity
  ```

### Step 2：进入新模块目录并完成编译验证
```bash
cd code-monitor
cp config.yaml.example config.yaml
make install && make lint && make test && make build
```

#### 脚本自动替你完成了哪 7 件事？
1. **命名安全校验**：拦截非法字符以及与平台保留路由（`bench`、`shield`、`pipeline`、`pdm`、`gate`、`proto`、`api`、`admin`、`docs` 等）的冲突。
2. **Go 模块重命名**：更新 `go.mod` 为 `module code-monitor`，并将所有 `.go` 文件中的内部包导入路径统一替换为 `code-monitor/...`。
3. **后端核心常量注入**：更新 `config/config.go` 中的 `ModuleKey` (`monitor`)、`ServiceName` (`Code-Monitor`)、`AdminRole` (`monitor_admin`)、`TablePrefix` (`mon_`) 与 `DefaultPort` (`:8091`)。
4. **Makefile 与配置模板更新**：将编译产物二进制名改为 `code-monitor-server`，同步更新 `config.yaml.example` 中的端口与表前缀说明。
5. **Vite 模块联邦对齐**：更新 `frontend/vite.config.ts` 中的 `federation.name = 'monitor'`、`base = '/monitor/'`、开发端口 `5181` 及 API 本地代理端口 `8091`。
6. **前端常量与菜单导出对齐**：更新 `frontend/src/constants.ts` 与 `frontend/src/menu.ts` 的 `monitorMenuConfig`。
7. **打印宿主挂载配置**：在终端直接生成可粘贴至 `code-bench/config.yaml` 的 YAML 片段。

## 3. 配置数据库与共享密钥

复制配置模板并按本地环境修改：

```bash
cp config.yaml.example config.yaml
```

编辑 `config.yaml`，重点核对以下两处：
1. **`database`**：填写本地 PostgreSQL 连接信息（若希望直接复用 `code-bench` 的用户、部门与全局操作审计中心，请指向与 `code-bench` 相同的 `dbname`）。
2. **`auth.jwt_secret`**：**必须与 `code-bench/config.yaml` 中的 `auth.jwt_secret` 完全一致**，否则宿主门户签发的登录 Token 在访问你的子模块后端 API 时会返回 `401 Invalid token signature`。

## 4. 两种运行与验证方式

### 方式一：本地独立开发调试（无需启动 `code-bench`）
在日常编写业务逻辑与调试界面时，你可以完全脱离 `code-bench` 独立运行：

1. **安装前端依赖**：
   ```bash
   make install
   ```
2. **终端 1 —— 启动 Go 后端服务**：
   ```bash
   go run .
   ```
   > 首次启动时，若连接的是空数据库，系统会自动创建默认管理员账号 `admin@code-shield.com`（初始密码 `Admin@123456`，可通过环境变量 `ADMIN_EMAIL` / `ADMIN_PASSWORD` 覆盖）并写入 3 条示例业务数据。
3. **终端 2 —— 启动 Vite 前端热更新服务**：
   ```bash
   cd frontend && npm run dev
   ```
4. **访问验证**：打开浏览器访问 `http://192.168.56.18:5181/monitor/`（本机回环亦可访问对应端口），你将看到独立的登录页、调试侧边栏以及右上角的 **「切换亮色 / 切换暗黑」** 主题测试按钮！

---

### 方式二：挂接到 CodeBench 微前端组装台联调

> [!IMPORTANT]
> CodeBench 在运行时通过动态加载子应用的打包产物 `/<module_key>/assets/remoteEntry.js` 来挂载微前端。因此在挂接进 CodeBench 之前，子模块必须执行过前端构建（`make build`）。

1. **构建内嵌前端产物的单二进制并启动子服务**：
   ```bash
   make build
   ./code-monitor-server
   ```
2. **在 `code-bench/config.yaml` 注册网关（无需改动 `code-bench` 任何源码）**：
   ```yaml
   gateways:
     # ... 保留已有模块配置 ...
     monitor:
       url: "http://127.0.0.1:8091"
       title: "集群监控诊断"
       icon: "Activity"
       description: "实时监控集群节点健康状态、资源指标分析与智能告警看护"
   ```
3. **重启 `code-bench` 并访问门户**：
   访问 `http://192.168.56.18:8000` 登录工作台：
   * 首页工作台会自动出现 **「集群监控诊断」** 入口卡片；
   * 左侧导航栏会自动挂载一级菜单，点击后动态展开 `menu.ts` 中声明的 **「概览看板」**、**「示例条目管理」** 与 **「模块参数配置」** 二级菜单；
   * 顶栏切换亮色 / 暗黑主题时，子模块界面实时无闪烁同步切换！
